# PSI Bushing Lookup

A cross-reference of every current Penn State Industries (pennstateind.com) pen/pencil kit and the bushing set it turns against, built by scraping their live product pages directly.

Penn State Industries publishes an official "Bushing Book" PDF, but it's out of date and missing kits (e.g. `PKJ316CH` isn't in it, despite being a currently sold kit). This project scrapes the site itself instead, so it stays accurate as PSI adds or retires kits.

## Using it

Live at **https://wwe-corey.github.io/psi-bushing-lookup/** (GitHub Pages, served from `docs/`), or open [`docs/index.html`](docs/index.html) directly in a browser — it's a single self-contained file, no server needed. It has three views:

- **By Kit Design** — the ~270 physical kit designs, color/finish variants merged into one row each (best-effort — see caveats below)
- **By Exact SKU** — every individual product SKU, one per row, no grouping. This is the guaranteed-accurate view; use it when you need certainty for a specific kit.
- **By Bushing Set** — reverse lookup: given a bushing set ID, which kit designs use it.

All three are searchable (kit name, SKU, or bushing ID) and there are CSV downloads for the design-level and flat views under `docs/`.

## How it was built

Four scripts, run in order, each reading the previous step's output from `data/`:

```
python3 scripts/01_fetch_ids.py      # -> data/all_ids.txt
python3 scripts/02_scrape_products.py  # -> data/scraped_raw.json
python3 scripts/03_process.py          # -> data/final_data.json, data/compact_data.json, docs/*.csv
python3 scripts/04_build_html.py       # -> docs/index.html
```

No dependencies beyond the Python 3 standard library.

1. **`01_fetch_ids.py`** — fetches the pen-kits category page with the hidden `Per_Page=-1` query param (the only way to get the full list in one request; `?page=N` is silently ignored) and pulls every product ID out of the page's embedded Google Analytics `dataLayer` JSON.
2. **`02_scrape_products.py`** — fetches all ~700 individual product pages (10 concurrent requests) and extracts title, bushing set ID(s), and category from each via regex against the page's own "Bushings Needed" table row.
3. **`03_process.py`** — excludes starter-set/variety-pack/bundle SKUs and one mislabeled bushing-set product, then groups the remaining SKUs into kit designs by stripping known finish/plating words (Chrome, Gun Metal, Antique Brass, 24kt Gold, etc.) from titles and grouping by (normalized name, bushing set).
4. **`04_build_html.py`** — renders `docs/index.html` from `data/compact_data.json`. Commit and push `docs/index.html` and the site at the Pages URL above updates automatically.

## Re-scraping

PSI adds and discontinues kits over time. To refresh:

```
python3 scripts/01_fetch_ids.py
python3 scripts/02_scrape_products.py
python3 scripts/03_process.py
python3 scripts/04_build_html.py
```

`data/scraped_raw.json` is the raw per-SKU snapshot; everything downstream regenerates from it, so you only need to re-run step 1–2 against the live site, then 3–4 are pure local processing.

## Caveats

- **Grouping is a heuristic.** Color/finish words don't sit in a consistent position in PSI's titles (sometimes trailing "...Pen Kit in Chrome", sometimes mid-title "Astra Golden Twist Pen Kit"), so the finish-word list in `03_process.py` is curated from a word-frequency pass over real titles, not exhaustive by construction. If a kit's design grouping looks wrong, check it against the **By Exact SKU** view, which never groups anything.
- **"Not listed by PSI"** means the kit's own product page has no "Bushings Needed" field at all — confirmed by direct inspection, not a scraping failure. A handful of kits (mostly Protura and Pool Cue Chalk Holder variants) are like this on PSI's site itself.
- **Bundles/starter sets are excluded entirely** from both the design and flat views (they bundle multiple designs rather than being one distinct kit), but are counted in `data/final_data.json`'s `excluded_bundle` list if you want to see what was left out.
